# Crypto Strategy Lab

فریم‌ورک متن‌باز برای:
- تعریف ده‌ها استراتژی ترید کریپتو (ICT، Smart Money Concepts، پرایس اکشن، کلاسیک، رنج/RTM)
- بک‌تست همه‌ی آن‌ها روی دیتای تاریخی بایننس
- اجرای خودکار (زمان‌بندی‌شده با GitHub Actions) که سیگنال زنده تولید می‌کند،
  به ربات تلگرام شما می‌فرستد و **پوزیشن فرضی (پیپر‌تریدینگ)** باز می‌کند
- گزارش ماهانه‌ی خودکار که عملکرد هر استراتژی را مقایسه می‌کند

⚠️ **این ابزار توصیه مالی نیست.** بک‌تست و پیپر‌تریدینگ فقط برای ارزیابیِ
منطق استراتژی‌هاست؛ عملکرد گذشته تضمین‌کننده آینده نیست و ترید واقعی ریسک
از دست دادن سرمایه دارد. قبل از استفاده از پول واقعی، حداقل چند ماه با
نتایج پیپر‌تریدینگ روی چند بازه‌ی زمانی مختلف مطمئن شو.

## دو ویژگی کلیدی طراحی

**۱. هر استراتژی روی تایم‌فریم مخصوص به خودش اجرا می‌شود.**
یک تایم‌فریم مشترک برای همه‌ی استراتژی‌ها منطقی نیست - مثلاً ICT Silver
Bullet ذاتاً برای 5m طراحی شده، ولی Golden Cross 50/200 روی 1d معنا
دارد. هر کلاس استراتژی در کد یک `timeframe` مخصوص به خودش دارد
(لیست کامل در `STRATEGIES.md` یا با `python -m strategies.registry`) و
هم بک‌تست هم اجرای زنده دقیقاً همان تایم‌فریم را برای همان استراتژی
واکشی می‌کنند.

**۲. هر استراتژی در تلگرام «جدا» دیده می‌شود.**
اگر چت تلگرامت یک **گروه با Topics فعال** باشد، ربات برای هر استراتژی
یک تاپیک مجزا می‌سازد (فقط یک‌بار) و همه‌ی پیام‌های آن استراتژی -
سیگنال باز شدن، بسته‌شدن با سود/ضرر، خلاصه ماهانه - همیشه داخل همان
تاپیک می‌روند. یعنی می‌توانی وارد تاپیک `ict_judas_swing` بشوی و فقط
تاریخچه‌ی همان استراتژی را ببینی، بدون نیاز به فیلتر کردن پیام‌ها.
اگر Topics فعال نکنی، سیستم خودش fallback می‌زند و پیام‌ها را با تگ
واضح استراتژی در همان چت عادی می‌فرستد - چیزی خراب نمی‌شود.

## ساختار پروژه
```
crypto-strategy-lab/
├── data/fetcher.py          # واکشی OHLCV از بایننس (ccxt)
├── strategies/
│   ├── base.py               # کلاس پایه Strategy و Signal
│   ├── indicators.py         # اندیکاتورها + ابزار ساختار بازار (BOS/CHoCH/OB/FVG/Sweep)
│   ├── ict/strategies.py
│   ├── smc/strategies.py
│   ├── price_action/strategies.py
│   ├── classic/strategies.py
│   ├── range_rtm/strategies.py
│   └── registry.py           # کشف خودکار همه استراتژی‌ها
├── backtest/
│   ├── engine.py              # موتور بک‌تست بار-به-بار
│   ├── metrics.py             # وین‌ریت، پروفیت‌فکتور، دراودان، ...
│   └── run_backtest.py        # اسکریپت اجرای بک‌تست روی همه استراتژی‌ها
├── live/
│   ├── telegram_bot.py
│   ├── paper_trader.py        # دفتر پوزیشن فرضی (JSON)
│   └── runner.py              # اسکریپتی که GitHub Actions هر ساعت اجرا می‌کند
├── reports/monthly_report.py  # گزارش پایان ماه + ارسال تلگرام
├── .github/workflows/
│   ├── live_signals.yml       # cron: هر ۵ دقیقه (کوچک‌ترین تایم‌فریم = 5m)
│   └── monthly_report.yml     # cron: روز اول هر ماه
├── STRATEGIES.md              # کاتالوگ کامل ۱۰۰ استراتژی (۴۰ تا الان پیاده‌سازی شده)
└── config.example.yaml
```

## نصب و اجرای محلی

```bash
git clone <repo-url>
cd crypto-strategy-lab
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp config.example.yaml config.yaml
# config.yaml را ویرایش کن: نمادها، توکن تلگرام و chat_id
```

### دیدن لیست همه استراتژی‌های ثبت‌شده
```bash
python -m strategies.registry
```

### گرفتن بک‌تست روی همه استراتژی‌ها
```bash
python -m backtest.run_backtest
# یا فقط یک دسته:
python -m backtest.run_backtest --category ict
python -m backtest.run_backtest --symbol "BTC/USDT"
```
نتیجه در `results/backtest_summary.csv` (رتبه‌بندی‌شده بر اساس بازده خالص)
و معاملات تک‌تک هر استراتژی در `results/trades/` ذخیره می‌شود.

### ساخت ربات تلگرام (اگر نداری)
1. در تلگرام به [@BotFather](https://t.me/BotFather) پیام بده، `/newbot` بزن، توکن را کپی کن.
2. با ربات جدیدت یک پیام بفرست، بعد به آدرس زیر برو تا `chat_id` را پیدا کنی:
   `https://api.telegram.org/bot<TOKEN>/getUpdates`
3. توکن و chat_id را در `config.yaml` (اجرای محلی) یا Secrets گیت‌هاب (اجرای خودکار) بگذار.

### راه‌اندازی تاپیک جدا برای هر استراتژی (اختیاری ولی پیشنهادی)
اگر می‌خواهی هر استراتژی یک ساب‌چت مجزا در تلگرام داشته باشد (تا بعداً
راحت تحلیل کنی)، به‌جای چت خصوصی با ربات یک **گروه** بساز:
1. یک گروه تلگرام جدید بساز (نه کانال).
2. `Group settings → Edit → Topics` را روشن کن (گروه را Forum کن).
3. ربات را با `/newbot` که ساختی به گروه اضافه کن و **Admin**ش کن؛
   حتماً دسترسی **Manage Topics** را برایش فعال کن.
4. `chat_id` همین گروه را در `config.yaml` بگذار (گروه‌ها معمولاً یک
   عدد منفی دارند، مثل `-1001234567890` - همان از `getUpdates` بیرون می‌آید).
5. `telegram.use_topics: true` را در config نگه دار (پیش‌فرض هم همینه).

از این به بعد، اولین باری که هر استراتژی سیگنال بدهد، ربات خودش یک
تاپیک به اسم آن استراتژی می‌سازد و از آن به بعد همه‌ی پیام‌های همان
استراتژی (باز شدن، بسته‌شدن، خلاصه ماهانه) داخل همان تاپیک می‌روند.
اگر این مراحل را انجام ندهی، هیچ اشکالی ندارد - سیستم به‌صورت خودکار
پیام‌های معمولی با تگ استراتژی می‌فرستد.

### اجرای دستی سیگنال زنده (تست محلی)
```bash
python -m live.runner
```

### اجرای دستی گزارش ماهانه
```bash
python -m reports.monthly_report --year 2026 --month 8
```

## راه‌اندازی اجرای خودکار روی GitHub

1. این پروژه را در یک ریپازیتوری روی گیت‌هاب Push کن.
2. برو به `Settings → Secrets and variables → Actions → New repository secret` و دو مقدار زیر را اضافه کن:
   - `TELEGRAM_BOT_TOKEN`
   - `TELEGRAM_CHAT_ID`
3. مطمئن شو `Settings → Actions → General → Workflow permissions` روی
   **Read and write permissions** تنظیم شده باشد (چون ورک‌فلوها خودشان با
   `git push` نتیجه را کامیت می‌کنند).
4. همین! ورک‌فلوی `live_signals.yml` هر ۵ دقیقه خودش اجرا می‌شود (چون
   کوچک‌ترین تایم‌فریم بین استراتژی‌ها 5m است)، برای هر استراتژی روی
   تایم‌فریم خودش دیتا می‌گیرد، سیگنال‌های جدید را به تاپیک همان استراتژی
   در تلگرامت می‌فرستد، پوزیشن فرضی باز/بسته می‌کند و دفتر پوزیشن‌ها
   (`results/live/positions.json`) را در ریپو آپدیت می‌کند. اجرای مکرر
   کاملاً بی‌خطر است چون تا پوزیشن باز قبلی یک استراتژی بسته نشود، آن
   استراتژی سیگنال جدید تکراری نمی‌فرستد.
   ورک‌فلوی `monthly_report.yml` هم روز اول هر ماه هم یک رتبه‌بندی کلی
   و هم یک خلاصه‌ی جدا برای هر استراتژی (داخل تاپیک خودش) می‌فرستد.
5. اگر می‌خواهی زودتر تست کنی: در تب **Actions** ریپو، روی هرکدام از
   ورک‌فلوها بزن → **Run workflow** (اجرای دستی، بدون نیاز به صبر کردن تا کرون بعدی).

### تغییر نمادها یا اضافه‌کردن تایم‌فریم جدید
نمادها را در `config.example.yaml` (`exchange.symbols`) تغییر بده.
تایم‌فریم هر استراتژی داخل خودِ کلاس آن استراتژی است (`timeframe = "..."`)
نه در config - برای تغییرش کافی‌ست همان خط را در فایل دسته مربوطه
(مثلاً `strategies/ict/strategies.py`) ویرایش کنی. اگر یک استراتژی با
تایم‌فریمی که قبلاً هیچ استراتژی دیگری نداشت اضافه کنی، runner و
بک‌تستر خودشان آن تایم‌فریم جدید را هم به‌صورت خودکار واکشی می‌کنند -
فقط اگر آن تایم‌فریم کمتر از 5 دقیقه بود، کرون `live_signals.yml` را
هم متناسب تغییر بده.

## بعد از اینکه چند هفته/ماه دیتا جمع شد
- `results/backtest_summary.csv` و گزارش‌های ماهانه در `results/reports/`
  را با هم مقایسه کن — استراتژی که هم در بک‌تست تاریخی و هم در پیپرتریدینگ
  زنده winrate/PF پایدار داشته باشد، کاندیدای بهتری برای ادامه است.
- به تعداد معاملات دقت کن: چند ده معامله برای نتیجه‌گیری آماری کافی نیست.
- قبل از هر تصمیم برای ترید با پول واقعی، مدیریت ریسک (اندازه پوزیشن، حداکثر
  ضرر روزانه/ماهانه، عدم همبستگی بیش از حد بین چند استراتژی هم‌زمان) را جدا تعریف کن.
